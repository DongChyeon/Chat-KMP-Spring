# 03. 로그아웃한 기기의 Access Token은 언제까지 통하나

- 날짜: 2026-11-10
- 로드맵 단계: 1 (부숴보기)
- 관련 결정: ADR 0009(Access 15분), ADR 0016(로그아웃 후 Access Token 감수)

## 예측 (오너 작성)

질문: 로그아웃 직후, 로그아웃한 기기의 Access Token으로 `/me`를 호출하면 어떤 응답이 올까? 그 응답은 언제, 어떤 응답으로 바뀔까?

> 401 응답이 오고
> 클라이언트가 리프레쉬 토큰을 이용해서 Access Token을 갱신해서 호출하면 200 응답으로 바뀌어

## 실행

15분을 기다리지 않도록 Access Token TTL을 1분으로 줄여 서버를 띄운다. 코드와 설정 파일은 바꾸지 않는다.

```bash
docker compose up -d --wait
./gradlew :server:bootRun --args='--jwt.access-token-ttl=1m'
# 다른 터미널에서
./scripts/logout-window.sh 90 10
```

## 관찰

```
로그인 직후 /me                : 200
로그아웃                       : 204
로그아웃 직후 재발급           : 401 REFRESH_FAILED

로그아웃 후 경과(초)  /me 응답
         0  200
        10  200
        21  200
        31  200
        41  200
        51  200
        61  401 TOKEN_EXPIRED
        71  401 TOKEN_EXPIRED
        81  401 TOKEN_EXPIRED
```

- 로그아웃한 직후에도 그 기기의 Access Token으로 `/me`가 **200**으로 통과했다. TTL(1분)이 지날 때까지 계속 통과했다.
- 51초와 61초 사이에 `401 TOKEN_EXPIRED`로 바뀌었다. 토큰은 로그인할 때 발급됐으므로 정확히는 발급 후 60초에 만료된 것이다.
- 같은 기기의 Refresh Token은 로그아웃 직후부터 `401 REFRESH_FAILED`였다. 그래서 만료된 뒤 재발급으로 200을 되찾는 길도 막혀 있었다.

## 왜

예측과 두 군데가 달랐다.

**1. 로그아웃 직후 `/me`는 401이 아니라 200이다.**
인증 필터는 Access Token의 서명과 만료 시간만 확인하고 DB를 보지 않는다(ADR 0005, 무상태). 로그아웃이 지운 것은 `refresh_tokens`의 행뿐이고, 필터는 그 행을 조회하지 않는다. 그래서 서버 입장에서 로그아웃한 기기의 Access Token은 만료 전까지 정상 토큰과 구별되지 않는다. 운영 TTL(15분)이면 이 창이 최대 15분이다. ADR 0016 추가 결정에서 감수하기로 한 위험이 실제로 이렇게 보인다.

**2. 만료된 뒤 재발급해도 200으로 돌아오지 않는다.**
예측은 "로그인 상태에서 Access Token이 만료된 경우"의 흐름(401 → 재발급 → 200)이다. 로그아웃한 기기는 허용 목록의 행이 지워졌으므로 재발급이 `REFRESH_FAILED`로 실패하고, 앱은 로그인 화면으로 가야 한다(ADR 0014). 상태 코드는 둘 다 401이지만, 앱이 다음 행동을 고르는 근거는 에러 코드(`TOKEN_EXPIRED` → 재발급, `REFRESH_FAILED` → 재로그인)다.

**고칠 것인가**
지금은 고치지 않는다(ADR 0016). 정상 앱은 로그아웃할 때 로컬 토큰을 지우므로 이 창을 쓰지 않는다. 문제가 되는 것은 Access Token이 탈취된 경우다. 이 창을 좁혀야 할 때는 먼저 Access TTL을 줄이는 것을 검토하고, 즉시 차단이 필요해지면 차단 목록(jti)이나 세션 확인(sid)을 다시 결정 게이트에 올린다.
