## 맥락

서버 코드에서 DB를 어떤 방식으로 다룰지 정해야 한다.

## 선택지

### A. JPA (Hibernate)
- 장점: 국내 실무의 사실상 표준이다.
- 단점: 영속성 컨텍스트, 지연 로딩, N+1 등 배울 개념이 많고 SQL이 가려진다. Kotlin에서는 엔티티에 `data class`를 쓰기 어렵고 `open` 클래스와 기본 생성자 플러그인이 필요하다.

### B. Spring Data JDBC
- 장점: 단순하고 지연 로딩이 없다.
- 단점: 연관관계를 직접 다뤄야 하고, 실무 사용이 적다.

### C. jOOQ
- 장점: 타입 안전한 SQL을 직접 쓴다.
- 단점: 스키마에서 코드를 생성하는 설정이 필요하다.

### D. Exposed
- 장점: Kotlin과 가장 잘 맞는다.
- 단점: 생태계가 작고 Spring 연동 자료가 적다.

## 결정

A. JPA를 사용한다.

- SQL 로그를 켜서 실제로 나가는 쿼리를 확인하며 개발한다.
