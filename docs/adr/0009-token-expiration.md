# 0009. 토큰 만료 시간: Access 15분, Refresh 30일

- 상태: 채택
- 날짜: 2026-11-07
- 로드맵 단계: 1
- Issue: #3

## 맥락

JWT + Refresh Token 구조(ADR 0005)에서 두 토큰의 수명을 정해야 한다. Access Token이 만료되면 앱이 Refresh Token으로 조용히 재발급받으므로, 사용자는 Access Token 만료를 느끼지 못한다.

## 선택지

### Access Token (보통 5분 ~ 1시간)
- 짧게: 탈취되거나 강제 로그아웃했을 때 토큰이 살아 있는 기간이 짧다. 대신 재발급 요청이 늘어나고, 서버는 그때마다 Refresh Token 저장소를 조회한다.
- 길게: 재발급 요청이 줄지만, 강제 로그아웃해도 그 시간 동안 토큰이 유효하다.

### Refresh Token (보통 7일 ~ 수개월)
- 짧게: 탈취됐을 때 악용 기간이 짧지만, 사용자가 자주 다시 로그인해야 한다.
- 길게: 다시 로그인하는 일이 드물지만, 탈취되면 오래 악용될 수 있다.

## 결정

- Access Token: 15분
- Refresh Token: 30일

## 이유 (오너 작성)

> Access: 토큰 갱신 요청 횟수가 너무 많지 않도록 조절하고 탈취됐을 때의 피해를 막기 위해 15분으로 설정할게

> Refresh: 채팅앱이다보니 만료될때까지의 기간이 좀 더 길어도 될 것 같아

## 결과

- 두 값은 `application.properties` 설정값으로 둔다. 테스트에서는 짧게 줄여서 쓴다.
- 1단계 부숴보기: 강제 로그아웃한 뒤에도 Access Token이 최대 15분 동안 유효한지 확인한다.
- 3단계 참고: WebSocket은 보통 연결할 때만 토큰을 검사하므로, Access Token이 만료되거나 강제 로그아웃해도 이미 열린 연결은 자동으로 끊어지지 않는다. 처리 방식은 3단계에서 정한다.
