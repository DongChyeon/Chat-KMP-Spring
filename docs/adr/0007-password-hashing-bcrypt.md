# 0007. 비밀번호 해싱: BCrypt

- 상태: 채택
- 날짜: 2026-11-07
- 로드맵 단계: 1
- Issue: #3

## 맥락

비밀번호는 원문 대신 되돌릴 수 없는 해시로 저장한다. DB가 유출돼도 원래 비밀번호를 알아내기 어렵도록 일부러 느린 알고리즘을 쓴다.

## 선택지

### A. BCrypt
- 장점: 오랫동안 쓰인 업계 표준이다. Spring Security 기본값이라 추가 의존성이 없다.
- 단점: 입력이 72바이트를 넘으면 뒷부분을 무시한다. GPU 대량 공격 방어는 Argon2보다 약하다.

### B. Argon2id
- 장점: 메모리를 많이 쓰게 해서 GPU 대량 공격에 가장 강하다. OWASP 1순위 권장이다.
- 단점: Bouncy Castle 의존성이 필요하다. 로그인마다 메모리를 수십 MB 써서 동시 로그인이 몰리면 서버 메모리 압박이 생긴다.

### C. PBKDF2
- 장점: 추가 의존성이 없다. 보안 인증(FIPS)이 필요한 환경에서 쓴다.
- 단점: GPU 대량 공격에 가장 약하다.

## 결정

A. BCrypt를 사용한다.

## 이유 (오너 작성)

> 오랫동안 쓰인 업계 표준이고, 공부 환경에서 다른 라이브러리를 추가하거나 보안 인증이 필요하진 않을 것 같아

## 결과

- 72바이트 제한 때문에 회원가입 시 비밀번호 최대 길이를 검증한다.
- Spring Security의 `DelegatingPasswordEncoder`를 쓰면 해시 앞에 `{bcrypt}` 접두사가 붙는다. 나중에 알고리즘을 바꿔도 기존 비밀번호를 검증할 수 있다.
