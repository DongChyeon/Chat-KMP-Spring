# 0019. 채팅방 종류: 1:1(DIRECT)과 그룹(GROUP)을 모두 둔다

- 상태: 채택
- 날짜: 2026-11-10
- 로드맵 단계: 2
- Issue: #7

## 맥락

채팅방을 어떤 종류로 제공할지 정해야 한다. 3단계에서 서버는 메시지를 받으면 채팅방의 참여자에게 보낸다. 사용자와 채팅방은 N:M 관계다.

## 선택지

### A. 그룹 방만 (1:1도 참여자 2명인 그룹)
- 장점: 모델과 API가 하나라 단순하다. 생성, 참여, 나가기 규칙이 모든 방에서 같다.
- 단점: 같은 두 사람이 방을 여러 개 만들 수 있다. "이 사람과의 대화방"을 찾을 수 없다.

### B. 1:1 방만
- 장점: 두 사람의 조합이 곧 방이라 중복 방지에 집중할 수 있다. 참여 방식 결정이 거의 필요 없다.
- 단점: 그룹 방을 추가할 때 모델과 API를 고쳐야 한다. 참여, 나가기, 참여자 N명 조회의 의미가 작아진다.

### C. 둘 다 (종류 컬럼: `DIRECT` / `GROUP`)
- 장점: 실제 메신저와 같은 모델이다. 1:1 중복 방지와 그룹 참여를 모두 다룬다.
- 단점: 종류마다 규칙이 갈린다(1:1 방에는 제3자가 참여할 수 없고, 중복 방지는 1:1에만 건다). 생성 API에 분기가 생기고 범위가 가장 넓다.

## 결정

C를 선택한다.

## 이유 (오너 작성)

> 실제 메신저와 동일한 모델로 1:1뿐만 아니라 다대다 채팅도 구현하면서 그에 따른 복잡한 요구사항을 구현해보기 위함이야

## 결과

- 채팅방에 종류(`DIRECT`, `GROUP`)를 저장한다.
- `DIRECT` 방은 참여자가 정확히 2명이다. 다른 사용자가 참여할 수 없고, 같은 두 사람 사이에는 방이 하나만 있어야 한다.
- `GROUP` 방에만 참여 방식(초대, 공개 방, 초대 코드) 결정이 적용된다.
